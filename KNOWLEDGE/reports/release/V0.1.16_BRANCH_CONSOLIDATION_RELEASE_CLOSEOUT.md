## 11. 剩余已知风险

1. **Windows 安装器使用一次性 CI 证书签名，不是正式代码签名身份。**
   安装器自身 build record 明确写着
   `signing: signed with a throwaway CI certificate (not a release identity)`，
   签名者 `D5034083CCE28AEDE85C737B88E00C138866B6DF`，artifacts 名称也是
   `...-signed-test`。这是本仓库当前 pipeline 的设计，**不是本轮引入的问题**，
   但意味着用户下载安装时会出现 SmartScreen 警告。要消除它需要一份真实代码签名证书。
2. `jiejie-libbox-apple-0.1.16.tar.gz` 的 manifest 记录
   `gomobile_version: unknown`、`gomobile_source: unknown`（gomobile 二进制过期）。
   其余字段完整，不影响 libbox 自身的 sha256 与 parent_sha 可验证性。
3. **本机无法运行 `-race`**：无 cgo/mingw sysroot，也没有可用的 Linux 环境。
   `-race` 是 **NOT RUN，不是 PASS**——但它由 CI 的 `verify.yml` 覆盖，且该 run 在发布
   SHA 上成功。
4. `scripts/ci/test-release-artifacts.sh` 的 92 例套件在本机因 Windows 工具链缺口
   （缺 `od`、`tar` 是 bsdtar 不支持 `--sort=name`）无法完整跑完；该套件由
   `release-contract-verify.yml` 在 Linux runner 上执行，本版该 run 成功。
5. `verify-upstream-assumptions.sh` 校验的是 pinned sing-tun 的 `acceptLoop` 仍调用
   `recoverListener`、不再裸返回；它**不覆盖**本次新增的
   “listenConfig 只记一次” 不变式——那由 sing-tun fork 自己的
   `stack_system_listenconfig_test.go` 覆盖。
6. `wip/p0ab-stale-base`（纯本地）与 Linux 上无法移除的
   `perf/xhttp-rtt-pipeline-probe` 本地引用仍存在，理由见 §6。

