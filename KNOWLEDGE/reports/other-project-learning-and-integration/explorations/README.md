# explorations —— 已探索、暂不采用的方案

本目录保存“已经认真评估过、结论是不值得在本轮实施”的方案，目的是让后续 AI 不再盲目重试。**它不是待办列表。**

## 收录标准

只有满足以下条件的才写入本目录：

1. 方案属于**特别大的重构**（替换核心栈/生命周期模型、跨多个 owner 重写资源合同、迁移大量 native/子仓/客户端、长期维护平行系统），而不是小/中改。
2. 已按真实调用与可控小实验核查瓶颈、预期收益、侵入/维护/回归成本，并比较过“沿原架构的较小替代”。
3. 结论是 `NOT_ADOPTED_WITH_EVIDENCE`（必要时 reason=`DISPROPORTIONATE_REFACTOR`），且已保留本轮验证过的小/中改。

文件名：`<主题>-<日期>.md`。正文至少包含八个部分（问题与目标症状、原架构边界、候选与较小替代、证据等级、收益/成本比较、结论与状态、适用与重开条件、脱敏与提交/远端核验）。无实测的部分必须标 `INFERRED`，不得编造收益数字。

## 本轮状态

**01 没有产生本目录条目。** 01 的任务是现状、覆盖账与最小观测基础；本轮唯一被明确否决的“第二压力采样器/独立内存预算平台”属于边界决定（见 `../DECISIONS.md` D-01-07），没有把任何特别大重构推进到需要八节结案报告的程度。02–12 若评估出此类方案，在此追加。
