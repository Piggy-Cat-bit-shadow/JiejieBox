## 批 1 已落地（04-A / 04-B 首个 owner / 04-C）

### R01 首个接线（04-A）：owner 可达数，不是资源数

- `adapter/residency.go`：`ResidencyOwnerCount{Reachable, Releasable}`、`ResidencySnapshot`、
  `ResidencyReporter`。类型注释明确写死语义：**owner-reach**，不是 active/idle/draining、不是连接数、
  不是终结数；关闭调用成功也不证明资源已释放。
- `route/reference.go`：新增 `eachReusableOwner(kind, owner)` 单一枚举，`retireIdleResources`、
  `retireSuspectResources` 与新的 `ResidencySnapshot()` 共用。新增 owner 类别若漏进
  `residencyCountFor` 会 panic，而不是从报告里静默消失。`Start` 在存在 service registry 时注册
  `adapter.ResidencyReporter`（接口键，route 不依赖 oomkiller）。
- `service/oomkiller`：顶层加性 metadata 键 `residency`（与 `resourceGuard`/`memoryReclaim` 同通道），
  形状 `{"measure":"owner-reach","outbounds":{...},"endpoints":{...},"dnsTransports":{...},
  "httpClients":{...}}`，每类只报 `reachableOwners`/`releasableOwners`；无 reporter 时不写该键。
- 测试：route 断言四类计数、纯读（不动作/不拨号）、无 manager 时为 0、注册能力、生产 HTTP client
  manager 仍实现 `IdleConnectionReleaser`；oomkiller 断言形状、语义标记、缺省与真实 `metadata.json`
  加性写入。

### R01 首个真实 owner（04-B）：XHTTP XMUX

- `transport/v2rayxhttp/xmux.go` 新增池内库存 `xmuxPoolStats`（未导出；与 03 `packetUplink.stats()`
  同层，供驻留观测与测试）：
  `Generation`、`Pooled`、`Active`、`Idle`、`Draining`、`DrainingOldGeneration`、`Opened`、`Released`。
- `Generation` 是**池本地**的复用边界计数（`RetireSuspect` 递增），不是 runtimecoord 的网络代次；
  旧代 draining 与新代 pooled 可分开计数。
- `Released` 只在底层 `conn.Close()` 真正执行时 +1（deferred close 由最后一个 stream 的
  `addOpenUsage(-1)` 触发），一次连接最多计一次；不变量 `Opened == Pooled + Draining + Released`
  在每个状态点成立。活跃流在 boundary/Close 后仍持有 transport（`closes()==0`）。
- 边界：HTTP/2 库内部 idle 缓存是另一个 owner，本包不可观测，标 `NOT_VERIFIABLE_HERE`；H2/QUIC/
  AnyTLS/Cronet/Mieru/WG 的实际所有权盘点未做。

### R07 有界关闭诊断（04-C）

- `adapter.Scope.Close`：关闭队列改为带名字的 `scopeCleanup`；drain 记录 `total/completed/current`；
  watchdog 默认 `constant.StopTimeout`，**一次性**，超时打印 owner/阶段、已完成/待处理数、经过时间，
  以及 4 KiB 预算的 all-goroutine 栈；`defer` 停表，panic 路径也不遗留计时器。
- 诊断不改变关闭语义：不跳过、不取消、不重排 cleanup；`Close` 的结果、错误过滤、并发 Close 汇合
  行为不变；本机 `-race` 通过。
- `Scope.AddNamed` 供 `Box` 的 5 个 raw cleanup 命名（runtime coordinator、log factory、url-test
  history、debug HTTP server、NTP）；component cleanup 已由 `Scope.Start` 自动命名。
- `Box.close` 只增加顶层阶段耗时（status-view / pause-callback / power-governor / scope）的 debug
  行，不参与任何决策；源码核对确认前三段有界非阻塞，唯一无界段是 scope drain，因此 watchdog 只在
  Scope，一处，不新建第二关闭控制器。
