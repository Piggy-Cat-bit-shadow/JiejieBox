## 2. Blocker 1 — release tooling trust boundary: CLOSED

`check out the release tooling` had `path: tooling` and no `ref`, so the checker came from the
dispatched branch while the artifacts came from the tag.

Pinned to `${{ inputs.tag }}`, so `PRODUCT_SHA == TOOLING_SHA` by construction, plus a new step that
**proves** it at run time and writes both SHAs to the run summary. A future edit that reintroduces a
floating checkout fails there rather than silently reverting.

**A first attempt at this failed the contract**, and the failure was correct: the identity step
interpolated `${{ inputs.tag }}` into three places inside `run:`, which the gate rejects because the
value would become shell syntax rather than data.

```text
FAIL  inputs.* is passed as data, never interpolated into run:
```

Fixed by passing the tag through a step-level `env:` entry as `INPUT_TAG`, matching the convention the
file already uses for `INPUT_DRY_RUN`. **The pin itself was never in question and was not reverted.**

```text
Release contract verification #77  = success
    PASS: all 92 cases behaved as required
    PASS  inputs.* is passed as data, never interpolated into run:
    release workflow structure: 89 passed, 0 failed
```

## 4. Blocker 3 — macOS stability: CLOSED, on real Darwin

The brief required this be proven by a real Actions run, and it now has been. Two fixes, then
`client-macos.yml`.

### 4.1 The establishing reading (previous round, now CONFIRMED on Darwin)

`measuredSocketsPerStandardBind` sampled the census **once** and failed immediately on 0. The run
proves this fix landed:

```text
SOCKETS_PER_STANDARD_BIND=2 (established on this machine)
```

The old failure text — `Should not be: -1` / `no settled reading was ever taken` — is **gone**.

### 4.2 The pause-time census assertions

Real Darwin then surfaced the next one, which had been recorded and left open:

```text
FAIL: TestAdvGItem7TheTwoWitnessesAgreeWheneverNothingIsReopening
cycle 0: settled pause
Should be zero, but was 2
```

The distinction that matters, verified in the pinned dependency rather than assumed:

```text
pause return != receiver goroutine already absent from runtime.Stack

device.go:804   netc.stopping.Add(len(recvFns))
receive.go:85   device.stopping.Done()   as RoutineReceiveIncoming leaves
device.go:703   netc.stopping.Wait()     last statement of closeBindLocked
```

`Down()` **does** join the receivers functionally. What lags is the **witness**: a census reads
`runtime.Stack`, and a goroutine that signals its WaitGroup from inside a `defer` is still on that
stack while it unwinds. The claim is therefore "no receiver **leak**", not "no receiver synchronously
vanished" — and a census that never reaches zero still fails.

Both sites now use `require.Eventually(..., 10s, 2ms, ...)` — the cadence the file **already** used for
the identical zero-census wait at `:76-79`, whose comment states the same reason. That sibling had the
grace and these two did not; the inconsistency was the defect.

**`udpPortIsFree` assertions were left immediate, deliberately.** They are the stricter claim and are
correct as immediate assertions: `closeBindLocked` calls `netc.bind.Close()` under the net lock before
`stopping.Wait()`, so the OS answers it by the time `Down()` returns. Making them `Eventually` would
have loosened a claim that is currently exact.
