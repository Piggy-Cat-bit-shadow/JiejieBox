# B8 data reconciliation

Source of truth is raw JSON. `table.md` in this directory is generated by
`scripts/perf/report-b8.py`; it validates every run against schema v1.2 and checks
the count invariants before printing a row. No number below was typed from a
previous report.

## What changed semantically

- `lost`/`loss_percent` exist only when `loss_estimable=true` (complete quiet
  observation and exact sequence tracking).
- `not_returned_by_deadline` is always recorded; it is a deadline fact.
- The target count is per measured epoch, so warmup cannot enter it.
- A 12 s observation was added for the TrustTunnel 500 pps cell because 8 s was
  still marginal; the longer window is reported separately and is the
  authoritative one for that cell.

## Interpretation

- MASQUE at 500 pps genuinely loses a third to a half of the datagrams; the target
  ingress is also short (1168-1857 of 2500), so the drop is on the client/tunnel
  path before the target, consistent with the earlier qdisc/socket evidence (veth
  drops only ~1 %, socket errors zero).
- TrustTunnel at 500 pps does **not** lose the datagrams in the new window: it
  delivers all 2500, but the tail takes 7-9 s. The old 75-82 % figure was an
  observation-window truncation, not network loss. This is a latency/queue
  collapse, not a loss result.
- The rate threshold is therefore transport-specific: MASQUE starts losing
  between 250 and 500 pps; TrustTunnel keeps data but accumulates multi-second
  delay. Both remain `UNRESOLVED` at the root-cause level; the measurement is now
  able to tell the two apart.

## Legacy data

- `results/b8-final/` (old 2 s drain, dirty runner): `PROVENANCE_INCOMPLETE` /
  `SUPERSEDED`; kept for history, see its `PROVENANCE.md`.
- `results/b8-rate/`: runner clean (only an untracked doc), but old semantics;
  `curve.md` is now regenerated from raw JSON and every row is labelled
  `legacy_*`. Its TrustTunnel 500/2 s rows are `legacy_incomplete`, with
  `not_returned` shown and no loss percentage. This removes the earlier
  `0 / 77.2 / null` summary error.
- No historical JSON was edited.

## Remaining unknown

The exact queue inside MASQUE (device/CONNECT-IP queue vs QUIC send buffer) is
still `NOT_AVAILABLE`; the new data bounds it to the client/tunnel side and
separates MASQUE loss from TrustTunnel delay, but does not name the queue.
