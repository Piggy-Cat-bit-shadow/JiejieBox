# Provider

Outbound providers publish nodes from a document that is external to the configuration: a
subscription URL, a local file, or the configuration itself. The nodes join the same outbound
namespace the static `outbounds` use, and a [selector](/configuration/outbound/selector/) or
[urltest](/configuration/outbound/urltest/) names the provider to include them.

A provider only supplies **outbounds**. It never replaces the configuration's DNS, route, inbounds or
experimental settings: a subscription that also contains those keys has them ignored, and only its
`outbounds` are read.

### Structure

```json
{
  "providers": [
    {
      "type": "remote",
      "tag": "airport",
      "url": "https://example.com/sing-box-subscription",
      "update_interval": "6h"
    }
  ],
  "outbounds": [
    {
      "type": "selector",
      "tag": "proxy",
      "outbounds": ["self-hosted"],
      "providers": ["airport"]
    }
  ]
}
```

### Fields

| Key         | Format                  |
|-------------|-------------------------|
| `type`      | `remote`, `local` or `inline` |
| `tag`       | Provider tag            |

The provider tag is required to be unique among providers. It is also the prefix of every node tag:
a node named `hk-01` inside provider `airport` is published as `airport/hk-01`. Use
`providers: ["airport"]` on a group to include every node of that provider.

### Remote

Downloads the document from `url`, caches the last known good copy, and refreshes it on
`update_interval`.

```json
{
  "type": "remote",
  "tag": "airport",
  "url": "https://example.com/sing-box-subscription",
  "path": "provider/airport.json",
  "initial_path": "provider/airport-initial.json",
  "user_agent": "sing-box",
  "http_client": "download",
  "update_interval": "6h",
  "include": "hk|sg|jp",
  "exclude": "expired"
}
```

| Field             | Description                                                                    |
|-------------------|--------------------------------------------------------------------------------|
| `url`             | Required. Subscription URL.                                                    |
| `path`            | Cache file for the downloaded document. Mutually exclusive with `initial_path`. |
| `initial_path`    | Document used only when there is no cache and the first download fails.         |
| `user_agent`      | `User-Agent` sent with the request. Conflicts with `http_client.headers`.       |
| `http_client`     | [HTTP client](/configuration/shared/http-client/) used to download.            |
| `download_detour` | Deprecated. Outbound tag used to download. Use `http_client` instead.           |
| `update_interval` | Refresh interval, minimum `1h`. Defaults to `24h`.                              |
| `include`         | Regexp: only nodes whose **rendered tag** matches are published.                |
| `exclude`         | Regexp: nodes whose **rendered tag** matches are skipped. `exclude` wins.       |
| `health_check`    | See below.                                                                      |

Without `path`, the cache lives in the configured [cache file](/configuration/experimental/cache-file/)
and disappears when that is disabled. A provider that has no cache and cannot reach its URL at start
starts with zero nodes; its groups report "no available member" on the dial path until a download
succeeds, and the first download is retried on the update interval.

The download is asynchronous: `sing-box` never blocks the start of the Box on a subscription URL.

### Local

Reads the same document shape from a local file and reloads it when the file changes.

```json
{
  "type": "local",
  "tag": "local-nodes",
  "path": "provider/local.json"
}
```

### Inline

Declares the nodes in the configuration itself. Useful for testing a node set without a subscription,
and for a configuration that is generated by an external tool.

```json
{
  "type": "inline",
  "tag": "inline-nodes",
  "outbounds": [
    {
      "type": "socks",
      "tag": "local-socks",
      "server": "127.0.0.1",
      "server_port": 1080
    }
  ]
}
```

### Health check

The optional health check measures every published node and records the result in the shared
URL-test history, which is the same store the urltest group reads. It does not select anything by
itself; a group's own configuration decides what it uses.

```json
{
  "health_check": {
    "enabled": true,
    "url": "https://www.gstatic.com/generate_204",
    "interval": "10m",
    "timeout": "3s"
  }
}
```

| Field      | Description                                             |
|------------|---------------------------------------------------------|
| `enabled`  | Enable the periodic check.                               |
| `url`      | URL to request.                                          |
| `interval` | Check interval, minimum `1m`. Defaults to `10m`.         |
| `timeout`  | Per-node timeout. Defaults to `3s`.                      |

### Node document

The document may be either a complete sing-box configuration or an object containing only
`outbounds`; every other top-level key is ignored. Nodes are decoded with the same option types and
the same outbound registry as static outbounds, so every protocol this build supports is accepted
without a second parser.

Nodes are filtered in this order:

1. `selector`/`urltest`/`loadbalance`, `direct`, `block` and `dns` entries inside the document are
   skipped.
2. `exclude` and `include` of the provider are applied to the rendered tag.
3. A tag repeated inside one document is renamed deterministically: the first occurrence keeps the
   name, later ones become `name (2)`, `name (3)`.

A `detour` that names a sibling node is rewritten to that sibling's rendered tag. A `detour` that
names anything else is cleared: the provider cannot know whether the main configuration still has
that tag, and a node with a dangling dependency would fail to create.

### Updates

An update is a diff. A node whose options are unchanged keeps its live object and therefore its
connections; a changed node is prepared and started before the previous object is unlinked; a node
whose replacement fails keeps the previous object in service. A subscription refresh that only
reorders or reformats entries does not disturb traffic.

`update_interval` is the minimum spacing between downloads. A manual refresh is not exposed through
the Clash API in this version; the provider refreshes on its own schedule.

### Group integration

- A group may name several providers.
- `use_all_providers` includes every configured provider; the set is resolved at start.
- A provider node is addressed by its rendered tag, so `default` and the Clash API see
  `airport/hk-01` exactly as the configuration does.
- When a refresh removes the member a group had selected, the group falls back in the documented
  order (stored selection, default, first member); when the member survives, the selection is kept.
- A group with no members yet (a provider has not published anything) starts successfully and fails
  the dial with a message naming the group, rather than silently selecting an unconfigured node.
