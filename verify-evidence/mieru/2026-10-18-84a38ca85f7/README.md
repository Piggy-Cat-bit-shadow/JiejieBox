Tree: `testing` @ `84a38ca85f7a46b3910147148dd349da20bb5c17`
Question: same host, same official-SDK server, same local SOCKS5 entry — is this fork's Mieru client
faster, and where does the difference live?

Mihomo v1.19.32 (SDK v3.38.0, product comparison only) also ran: it beats the target on the
high-mux TCP cells (target/Mihomo 0.95 download, 0.85 upload), while the target wins low-mux TCP
download (1.07x) and UDP-transport upload (1.27x). This confirms the target's TCP-upload weakness
rather than hiding it; see `decisions.md` E6.

The UDP-echo win is attributed to this tree's UoT framing (E1), not to the cipher or the server: both
clients used the same official server and the same echo target. The 6% TCP-upload gap is the one
repeatable regression and is left visible for the debug round.

## What this evidence does not say

- It is not a mita comparison: the server is the official SDK entry point because mita has no Windows
  build and this host has no WSL/Docker.
- It is not an adapter-memory comparison: the target process includes the sing-box core and mixed
  inbound. RSS is product context only.
- It is not a WAN/last-mile result: every peer is loopback on one host.
- mbox, extended, Hiddify and Mihomo were not runnable here; see `decisions.md` E6 for the exact
  blockers. No numbers were invented for them.
