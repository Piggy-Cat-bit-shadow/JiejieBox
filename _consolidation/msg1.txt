chore(consolidation): absorb closure/0.1.6-static-validation-final-wire

First consolidation merge: the maximal head of the 0.1.6 static-validation
closure line, which already contains (verified by ancestry, not by name)
integration/0.1.6-final-freeze, audit/upstream-absorb, the route-aware and
false-deny debug lines, p1c-iphone-device-closure, consumer-dns-parity and
group-crosskind. Those branches are therefore absorbed by this merge and are
not merged again.

Eight conflicts, each resolved on semantics rather than by picking a side:

  common/runtimecoord/platform_events.go
    Conflict hunks were comment text only for the identical code lines. Kept
    the testing wording, which is the newer explanation of the same guarded
    clear.

  common/runtimecoord/platform_events_test.go, common/sniff/quic_boundary_test.go
    Comment-only differences. Kept the testing side; in quic_boundary_test.go
    that side deliberately avoids quoting a source line number because the
    line moves, where the incoming text hard-coded quic.go:191.

  route/splice_diagnostics.go and its two test files
    The incoming side renames the counter to spliceReasonSuccess, the snapshot
    field to Successes, AcceptanceRatio to Ratio, and renders
    "splice diagnostics: ... successes=%d ratio=%.3f". The testing side had
    already retired exactly that wording: route/splice_diagnostics_test.go
    carries a source-level guard that fails if the producer says "Successes",
    "successes=", "splice diagnostics", "splice success" or "splice ratio",
    because that wording reads as a rate of working kernel splices when the
    counter only means "sing-tun accepted the handover". The incoming change is
    a revert of that fix, not new work, so the testing side is kept and the
    file is left byte-identical to testing. No functionality is lost: the
    normalized (comment-stripped, identifier-renamed) diff of the two sides is
    a rename and nothing else.

  go.mod / go.sum / test/go.sum
    The automatic merge already resolved go.mod to the union that must survive:
    sing at testing's newer v0.9.6-0.20261011105649-bde7ddda55ef, plus quic-go
    at v0.61.1-0.20261011111900-4d740322a18a and the sing-quic replace that
    only the incoming side carries. The sums were resolved as a union and then
    regenerated with `go mod tidy`, so every entry both sides need is present
    and the pin set above is intact.

  scripts/ci/build-apple-libbox.sh
    Two self-consistent designs collided: testing normalises the built
    framework to the repository root, the incoming side keeps it at
    _libbox_build/Libbox.xcframework and threads it through a $framework
    variable. The incoming design is the one the rest of the tree was written
    against - release-apple.sh:234 states that an artifact install "unpacks
    into the iOS client and never writes the repository root", and
    install_into's default source is the build-output path - so the incoming
    side is taken whole, and testing's unique stale-root cleanup
    (`rm -rf Libbox.xcframework`) is kept on top so a leftover root artifact
    cannot be mistaken for a successful build.

  clients/apple (gitlink)
    Three-way disagreement: 2a189686 in testing, 90a0e9ae incoming. Settled by
    the branch's own machine-readable evidence rather than by recency alone:
    fix/0.1.6-apple-pin-gates/verify-evidence/pin-identity.log requires
    APPLE_GITLINK == VERIFIED_APPLE_SHA == SUBMODULE_HEAD == APPLE_ORIGIN_MAIN,
    and all four are 90a0e9aef4c03df6cbc4cf170fe4bdef50bf1e07 there and on
    final-freeze and final-wire. verify-evidence/no-stale-pins.log names
    bb5309b4 and 5911580a as retired. In sing-box-for-apple, 90a0e9ae is the
    newest of the candidates (2026-10-11 19:14, "Merge branch
    'jiejiebox/p1c-iphone-device-closure' into main"). The gitlink is set to
    90a0e9ae, which also makes it agree with the VERIFIED_APPLE_SHA constant
    that the automatic merge had already taken from this branch. Testing's
    2a189686 was a 2026-10-10 ancestor and its own tree never matched its
    gitlink, so nothing coherent is discarded.
